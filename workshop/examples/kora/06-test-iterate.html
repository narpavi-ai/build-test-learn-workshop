Stage 6 — Test & Iterate (Build → Test → Learn)

Make it work, then make it believable

Walk the exact demo path, fix what breaks, and write down what you learned.

Inputs · the demo path & what broke

  • The path the audience will click?
    Type "Can we afford dinner out this weekend?" → see the answer + "$814 safe to spend" → tap a transaction for detail.
  • What broke / looked fake?
    (1) The API was stopped, so the question returned nothing. (2) "Safe to spend" felt high until the copy explained it was the whole remaining month. (3) No loading state on the first ask.

Outputs · fixes & learnings

Fixes applied

  • Restarted with npm run dev and confirmed all three endpoints respond.
  • Labelled the big number clearly ("Safe to spend this week") so it reads right on stage.
  • Added a "Kora is thinking…" loading state so the first ask never looks frozen.

Learnings — feed your next /1-problem

  • Surprise: people asked vague questions ("are we okay?") — the answer needs a confident default, not just keyword matches.
  • Idea change: the forecast nudge ("you're trending over on dining") may be a stronger hook than the raw number.
  • Next smallest thing: let a partner add a transaction and watch the safe-to-spend number move live.
